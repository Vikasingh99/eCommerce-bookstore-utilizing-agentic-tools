1. Use Case Overview

An online bookstore where a registered customer can browse a catalogue, manage a wishlist and cart, place an order and confirm payment. Three distinct journeys map to the feature set.

🏠 E-Store Home
1Login / Registration & User Authentication
2Order History with Buy-Again & Recommendations from Order History
3Access product catalogue per category
📖 Catalogue
5Select category of products
6Browse brands / publishers
7Product tagged with tentative delivery date · Related products appear
8Add product(s) to basket / cart
💳 Payment & Confirmation
9Select delivery address
10Initiate payment · Redeem gift points
11Payment confirmation
12Purchase confirmed · Cancel order within 48 hrs

Highlighted items are future-phase enhancements not yet in the current backend.

2. System Architecture

Three-tier architecture: browser client ↔ REST API server ↔ PostgreSQL database. No SSR data fetching — all data flows through client-side Axios calls to the Express API.

Registered User → User Login (JWT) → Home Page → Browse / Catalogue
Browse / Catalogue → Add to Cart → Order → Payment Processing → Shipment
Member (Auth) · Store / Catalog · Order · Payment · Shipping (future)

User
id Int PK autoincrement
name String
email String unique
passwordHash String
createdAt / updatedAt DateTime
→ refreshTokens, wishlistItems, cart, orders
Product
id Int PK
title, author, category, genre String
description, publishedBy, language String
price Decimal(10,2)
stock Int
imageUrl String
rating Decimal(3,1)
Cart + CartItem
Cart: id, userId unique, timestamps
CartItem: id, cartId, productId, quantity
Unique constraint: (cartId, productId)
Cascade delete on cart/product removal
Order + OrderItem
Order: id, userId, totalAmount, status
status: PENDING | CONFIRMED | CANCELLED
OrderItem: orderId, productId, quantity, price
price = purchase-time snapshot (immutable)

orderId unique FK
paymentReference String unique
paymentMethod: CARD | UPI | NET_BANKING
status: PENDING | SUCCESS | FAILED
amount Decimal(10,2)
WishlistItem · RefreshToken
WishlistItem: userId, productId
Unique: (userId, productId)
RefreshToken: token unique, expiresAt, revokedAt
Rotation: old token revoked on refresh

6. Authentication Architecture

TokenStorageLifetimeMechanism
Access Token (JWT)localStorage key: bookstore_access_token15 minutesAttached as Authorization: Bearer … by axiosSecure request interceptor
Refresh Token (JWT)Browser cookie bookstore_refresh_token (JS-readable, SameSite=Strict, 7 days)7 days (rotated)Read from cookie, sent in request body to POST /api/auth/refresh; old token revoked in DB

On 401 response: axiosSecure intercepts → reads refresh token from cookie → calls refresh endpoint → stores new access token → retries original request. On refresh failure → clear both tokens → redirect to /login.

10. Phased Delivery Plan

1

Phase 1 — Foundation (Complete ✅)

  • Backend: Express API, Prisma schema, all core routes, JWT auth, 67 passing tests
  • Frontend: Next.js App Router, AuthContext, axiosPublic/axiosSecure, all 10 routes, service layer
  • Core flows: Register → Login → Browse → Add to Cart → Checkout → Payment → Order Confirmation
2

Phase 2 — Order History & Cancel

  • Backend: Add GET /api/orders (list all orders for user)
  • Backend: Add PATCH /api/orders/:id/cancel with 48-hr window check
  • Frontend: /orders page — order history list with Buy-Again button
  • Frontend: Cancel Order CTA on order detail page
3

Phase 3 — Delivery Address

  • Backend: Add Address model (userId, line1, city, state, pincode, isDefault)
  • Backend: CRUD endpoints for user addresses
  • Backend: Attach selected addressId to Order on creation
  • Frontend: Address management page + address picker on checkout
4

Phase 4 — Catalogue Enhancements

  • Backend: Add estimatedDeliveryDays field to Product
  • Backend: Related products endpoint (same category, exclude current)
  • Frontend: Delivery date badge on product detail & catalogue cards
  • Frontend: Related books section on product detail page
5

Phase 5 — Recommendations & Gift Points

  • Backend: Recommendation service (most-bought categories from order history)
  • Backend: GiftPoint model, earn on purchase, redeem at checkout
  • Frontend: Recommended for You section on home page and catalogue
  • Frontend: Gift points balance display + redemption at checkout
